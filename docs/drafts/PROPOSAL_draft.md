## Game Concept

- **Game title:** Dungeon Explorer (지식의 상아탑)
- **Short description:** STL 컨테이너를 일절 쓰지 않고 직접 구현한 7가지 자료구조로 동작하는 C++17 터미널 카드 배틀 로그라이크. 6개 기술 트랙(핵·신소재·수소·환경기술·AI·그리드) 중 캐릭터 3명을 골라 공용 덱을 짜고, 3층 던전을 탐험하며 몬스터·이벤트를 거쳐 최종 보스를 격파한다.
- **Theme or story:** 시험이 카드가 되고 강의실이 전장이 된 대학 캠퍼스. "지식의 힘으로 싸워 이기는 자만이 지식의 상아탑 꼭대기에 오를 수 있다." 플레이어는 서로 다른 전공(트랙)을 가진 동료들과 탑을 올라 마지막 층의 교수님(보스)에게 도전한다.

## Planned World

3층 던전이며 각 층은 3×3(9개 방) 격자로, 현재 위치에서 상하좌우로 인접한 방으로만 이동한다(그래프 인접). 아래는 1층 배치이며 2·3층도 같은 격자·이동 규칙을 따른다(총 27개 방). 방 ID는 그래프 노드 번호(한 층 기준 `행×3+열`)이다.

방 종류: **S** 시작방 · **B** 전투방 · **E** 이벤트방 · **R** 휴식방 · **▲** 계단방(다음 층) · **X** 보스방.

```
1층 배치
[ S ][ E ][ B ]      0  1  2
[ R ][ B ][ B ]      3  4  5
[ E ][ R ][ ▲ ]      6  7  8
```

| Room ID | Room Name | Description | Connected Rooms |
|---|---|---|---|
| 0 | 시작방 (S) | 런 시작 지점. 파티 3명 선택과 25장 덱 빌딩 후 출발 | 1, 3 |
| 1 | 이벤트방 (E) | 선택형/강제형 이벤트가 1회 발생 | 0, 2, 4 |
| 2 | 전투방 (B) | 일반 몬스터와 카드 전투 | 1, 5 |
| 3 | 휴식방 (R) | HP+20 / ATK+1 / DEF+1 중 하나 영구 부스트(1회) | 0, 4, 6 |
| 4 | 전투방 (B) | 중앙 교차 전투방 | 1, 3, 5, 7 |
| 5 | 전투방 (B) | 전투방 | 2, 4, 8 |
| 6 | 이벤트방 (E) | 이벤트 발생 | 3, 7 |
| 7 | 휴식방 (R) | 영구 스탯 부스트(1회) | 4, 6, 8 |
| 8 | 계단방 (▲) | 진행 시 다음 층 (0,0)으로 이동 여부를 물음. 3층에서는 보스방(X)으로 대체 | 5, 7 |

> 3층의 (2,2)는 계단방 대신 **보스방(X)** 으로, 최종 보스 전투가 발생한다. 클리어한 전투·이벤트·휴식 방은 재방문 시 효과가 다시 발생하지 않는다.

## Planned Items

| Item Name | Location | Effect or Purpose | Value |
|---|---|---|---|
| 회복 포션 (heal) | 이벤트 보상 / 무료 보급 | 전투 중 사용 시 파티 HP 회복 | 전리품 1 |
| 공격력 강화 포션 (atkUp) | 이벤트 보상 / 무료 보급 | 일정 턴 공격력 버프 | 전리품 1 |
| 보호막 포션 (shield) | 이벤트 보상 / 무료 보급 | 일정 턴 방어막 부여 | 전리품 1 |
| 독 포션 (poison) | 이벤트 보상 / 무료 보급 | 적에게 지속 독 피해 | 전리품 1 |
| 폭발 포션 (explosive) | 이벤트 보상 / 무료 보급 | 적에게 즉발 피해 | 전리품 1 |
| 영구 스탯 상승 (rest) | 휴식방 (R) | HP+20 / ATK+1 / DEF+1 중 1택, 런 동안 영구 | 무료(방 1회) |
| 트랙 카드 (무기 대체) | 전투 보상 / 이벤트 / 보급 | 6개 트랙별 효과 카드를 덱에 추가 — 트랙 일치 시 보너스 효과 발동 | 전리품 1 |

## Planned Events or Monsters

**이벤트(6종)** — 이벤트방에서 1회 발생. 선택형(Choice)·강제형(Forced)이 있으며 한 선택지에 여러 효과가 동시 적용될 수 있다.
**몬스터** — 층별 트랙 색깔에 맞춘 일반 몬스터 + 최종 보스. 각 적은 트랙 속성과 행동 패턴(의도 예고)을 가진다.

| Event or Monster | Location | Trigger | Effect |
|---|---|---|---|
| 갑작스러운 정전 (강제 이벤트) | 이벤트방 | 진입 시 자동 | 전리품 +1, 파티 전체 피해 5 |
| 대학원생의 연구노트 (선택 이벤트) | 이벤트방 | 선택지 선택 | ①카드 1장 / ②카드 1장 + 파티 피해 4 |
| 교수님의 노트북 (강제 이벤트) | 이벤트방 | 진입 시 자동 | 보유 카드 1장 선택 제거(덱 최적화) |
| 도서관 (선택 이벤트) | 이벤트방 | 선택지 선택 | ①카드 1장 / ②HP 10 회복 / ③카드 1장 + 피해 5 |
| 너 내 동료가 돼라! (선택 이벤트) | 이벤트방 | 선택지 선택 | 새 트랙 동료와 파티원 교환 + 해당 트랙 카드 풀 추가 |
| 수상한 상점 (강제 이벤트) | 이벤트방 | 진입 시 자동 | 전리품으로 카드/포션 1개 무료 선택 |
| 일반 몬스터 (1층 신소재관 등 층별 12종) | 전투방 (B) | 진입 시 전투 시작 | 트랙 속성·행동 패턴별 공격/방어/디버프, 의도 예고 |
| 최종 보스 — 교수님/총장 (다단계) | 보스방 (X, 3층) | 진입 시 보스전 | 페이즈 전환형 패턴(광역·디버프·강공격) |

> 일반 몬스터는 층마다 주력 트랙을 달리해 배치한다(예: 1층 신소재 위주 → 상위 층으로 갈수록 핵·복합 속성). 보스는 HP가 높고 페이즈에 따라 패턴이 바뀐다.

## Data-Structure Mapping

> 과제 핵심: STL 컨테이너(`vector`/`list`/`stack`/`queue`/`map` 등) 사용 금지. 아래 구조는 모두 `include/ds/`·`include/map/`에 직접 구현한다.

| Data Structure | Planned Feature | Why This Structure Fits |
|---|---|---|
| Linked list | Inventory / 공유 덱 | 카드·포션의 추가·제거가 빈번하고 개수가 가변적 — 끝 삽입·앞 제거가 O(1)이고 크기 제한이 없어 적합 (`CardPool`, `Inventory`) |
| Stack | Undo movement / 카드 배정 취소 | 가장 최근 행동을 먼저 되돌리는 LIFO가 이동 되돌리기·카드 배정 취소와 정확히 일치. 그래프 DFS의 반복식 순회에도 사용 |
| Queue | 적 행동 패턴 순환 / 이벤트 결과 처리 | 적의 행동을 발생 순서대로 처리·순환시키는 FIFO가 자연스럽고(의도 예고), 한 이벤트의 여러 결과를 등록 순서대로 적용하는 데도 적합 |
| Binary search tree | Scores / search | 전투 효율 점수를 항상 정렬 상태로 유지 — 삽입·순위 조회가 평균 O(log n), 역중위 순회로 내림차순 랭킹 출력 |
| Graph | Room map | 방(노드)과 통로(엣지)로 불규칙한 던전 구조를 자연스럽게 표현하고, 인접 조회·DFS 길찾기에 바로 활용 |
| Sorting | Ordered display | 인벤토리·전투 통계·점수 등 화면 출력 시 필요에 따라 정렬(선택/삽입 정렬)을 직접 적용 |
| Dynamic array *(추가)* | 방 내부 아이템·몬스터 목록 | 인덱스 접근이 O(1)이고 ×2 증설로 가변 길이를 지원 — 방 1개의 적/아이템 목록에 적합 (`Room`) |

## Risks and Plan

| Risk | Mitigation Plan |
|---|---|
| 밸런스 조정 — 트랙별 카드/몬스터 수치가 너무 쉽거나 어려움 | 수치를 `Constants.h`·레지스트리로 분리해 한 곳에서 튜닝, 플레이테스트로 반복 조정 |
| BST 불균형 — 효율 점수가 비슷하면 편향 트리로 insert 최악 O(n) | 데이터 규모가 작아 실사용엔 무리 없음, 보고서에 한계로 명시(개선 시 AVL/RB-Tree) |
| 카드풀 고갈 — draw 연쇄 시 빈 덱 드로우 시도 | `CardPool::draw()`에서 `isEmpty` 체크 후 조기 반환(구현 완료) |
| 잘못된 입력 — 범위 밖 숫자·빈 입력으로 크래시 | 모든 입력 검증, 발표 전 경계값 시연으로 안정성 확인 |
| 발표 시간 부족 — 런 완주에 시간 소요 | `Constants.h`의 맵 깊이를 줄인 단축 런을 데모용으로 준비 |
